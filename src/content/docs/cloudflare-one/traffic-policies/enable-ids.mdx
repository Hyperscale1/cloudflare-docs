Cloudflare's Intrusion Detection System (IDS) monitors your traffic for known threat signatures using the [Advanced Network Firewall](/cloudflare-network-firewall/). This page explains how to enable IDS and configure detection rulesets.

After enabling IDS, configure [Logpush](/cloudflare-network-firewall/how-to/use-logpush-with-ids/) (required) to receive detection logs and use [Network Analytics](/analytics/network-analytics/) to view analyzed traffic.

## Enable IDS

You can enable IDS through the dashboard or via the API.

:::note
This feature is available for Cloudflare Advanced Network Firewall users. For access, contact your account team.
:::

<Tabs syncKey="dashPlusAPI"> <TabItem label="Dashboard">

1. In the [Cloudflare One](https://one.dash.cloudflare.com) dashboard, go to **Traffic policies**.
2. Select **Policy settings** and turn on **IDS**.

</TabItem> <TabItem label="API">

The API uses the [Rulesets Engine](/ruleset-engine/) to manage IDS. You create a _root ruleset_ (your account-level configuration) that references a _managed ruleset_ (Cloudflare's maintained IDS signatures) via an `execute` action.

To start using IDS via the API, first create a new ruleset in the `magic_transit_ids_managed` phase with a rule which is enabled.

1. Follow instructions in the [Rulesets Engine Page](/ruleset-engine/basic-operations/view-rulesets/) to view all rulesets for your account. You should see a ruleset with phase `magic_transit_ids_managed` and kind `managed`. This ruleset is provisioned by Cloudflare when your account has the Advanced Network Firewall add-on. If you do not see it, contact your account team to confirm the add-on is active. The managed ruleset ID will be used in the next step.

2. Create a new root ruleset with a single rule in the `magic_transit_ids_managed` phase by running:

```bash
curl https://api.cloudflare.com/client/v4/accounts/{account_id}/rulesets \
--header "Authorization: Bearer <API_TOKEN>" \
--header "Content-Type: application/json" \
--data '{
  "name": "IDS Execute ruleset",
  "description": "Ruleset to enable IDS",
  "kind": "root",
  "phase": "magic_transit_ids_managed",
  "rules": [
    {
      "enabled": true,
      "expression": "true",
      "action": "execute",
      "description": "enable ids",
      "action_parameters": {
        "id": "<MANAGED_RULESET_ID>"
      }
    }
  ]
}'
```

With this ruleset added, IDS will start inspecting packets and report any anomalous traffic. Next, [configure Logpush](/cloudflare-network-firewall/how-to/use-logpush-with-ids/) to start receiving details about the anomalous traffic.

## Disable or re-enable IDS

Use the rule created in the enable procedure to disable or re-enable IDS. The Rulesets API documentation describes [how to patch a rule](/ruleset-engine/rulesets-api/update-rule/).

For example, the following patch request sets the `enabled` field to `false` to disable IDS. The ruleset and rule ID from the ruleset created above are used below.

```bash
curl --request PATCH \
https://api.cloudflare.com/client/v4/accounts/{account_id}/rulesets/{root_ruleset_id}/rules/{rule_id} \
--header "Authorization: Bearer <API_TOKEN>" \
--header "Content-Type: application/json" \
--data '{
  "enabled": false,
  "expression": "true",
  "action": "execute",
  "action_parameters": {
    "id": "<MANAGED_RULESET_ID>"
  }
}'
```

Similarly, sending a patch request with the `enabled` field set to `true` will re-enable IDS.

## IDS rules

IDS inspects traffic in the following scenarios:

- **WAN-to-WAN:** Traffic routed between sites through [Cloudflare WAN](/magic-wan/).
- **Magic Transit ingress only:** Inbound traffic protected by Magic Transit, where outbound traffic returns directly to the origin (direct server return).
- **Magic Transit ingress and egress:** Both directions when Magic Transit has the [Egress option enabled](/reference-architecture/architectures/magic-transit/#magic-transit-with-egress-option-enabled).

## Next steps

After enabling IDS:

1. **Configure Logpush** (required) — IDS detections are not visible without a Logpush destination. Refer to [Configure Logpush for IDS](/cloudflare-network-firewall/how-to/use-logpush-with-ids/).
2. **Review traffic analytics** — All analyzed traffic appears in [Network Analytics](/analytics/network-analytics/). Use [GraphQL Analytics](/cloudflare-network-firewall/tutorials/graphql-analytics/) for programmatic queries.
